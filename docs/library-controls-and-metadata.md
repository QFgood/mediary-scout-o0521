# 媒体库重试与元数据状态

媒体库标题旁的「一键重试」与「同步网盘资源」并列。重试按当前账号与网盘处理最近 1000 条通知涉及的任务，每个作品只考虑最新记录；只有仍在追踪的、失败的可排队获取任务会重新排队。已完成、已取消追踪、未播出、已有活动任务及不能排队的巡检任务会跳过。结果显示重新排队及跳过数量，没有可重试任务时返回 0，不重新发起整个媒体库获取。相同失败任务再次点击不会重复创建任务。

搜索标题旁显示元数据加载状态；提交搜索时按钮也显示加载中。搜索和榜单返回后结束等待，元数据服务报错时显示连接异常。状态表示请求生命周期，不保证一定存在匹配结果。

桌面侧栏活动入口上方显示 TMDB / AniList API 可达状态和响应耗时。打开页面即检测，之后每 60 秒刷新；手机断点不显示也不发起请求，后台标签页暂停发起探测。服务端按账号合并 60 秒内的重复请求，避免多个标签页重复探测。

TMDB 检测沿用当前账号的直连 Token / 代理兜底链与 TMDB SOCKS5 设置；AniList 使用该账号的接口地址及 AniList SOCKS5 设置。显示的是应用服务端完成 API 请求的耗时，包括代理或兜底时间，不是浏览器到服务端的 ping。探测使用实际元数据请求，不调用 AI、Jev 或网盘；失败只返回状态，不返回密钥或底层错误内容。

未播 AniList TV / TV_SHORT / ONA / OVA 支持集数未定时预定。详情和媒体库显示已预定，后台等待排期与集数明确后追更，详见 [AniList 说明](anilist-development.md)。
