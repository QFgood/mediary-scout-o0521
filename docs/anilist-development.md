# AniList 双元数据与原生获取

当前版本补齐了此前“能搜索、但无 TMDB 映射就不能提交”的限制。支持的日本电视动画条目现在可以直接创建 AniList 原生任务，不需要配置 TMDB 季度映射。

## 使用方式

1. 搜索页切换到 AniList 元数据，输入作品名称。
2. 选中动画条目，点击「获取」。任务使用该条目的完整名称和别名，提交到当前网盘工作区。
3. 点击作品标题或「查看获取状态」进入 AniList 条目详情，查看集数、获取进度，或取消追踪。媒体库、活动页使用同一个来源身份链接。
4. 后台沿用现有队列、Worker、Agent 工具和网盘适配器。后续巡检向 AniList 查询播出进度，不会拿 AniList ID 请求 TMDB。

AniList 不保证中文译名覆盖；可以尝试日文、罗马字或英文名称。搜索与播出信息由普通 GraphQL API 获取，未使用 LLM 搜索元数据。

## 身份与目录

旧 TMDB 作品继续保存其真实 `tmdbId`。原生 AniList 动画保存：

```json
{
  "id": "anilist_anime_999",
  "source": "anilist",
  "anilistId": 999,
  "tmdbId": null,
  "episodeNumbering": "entry_relative"
}
```

上面的 ID 是测试占位值。原生条目与 TMDB 同编号、同标题的作品仍是不同目标。作品、季度、任务、集数和来源信息沿用现有 JSON 持久化，不需要数据库迁移；已通过内存、SQLite 和 PostgreSQL 契约检查。客户端进度和媒体库分组也按来源及 ID 区分。

原生目录为 `完整条目标题 (年份) {anilist-ID}/Season 01`。`Season 01` 只是现有执行器的条目内部集数分组，**不表示系列的第一季**；第三季或独立篇章保持自己的完整标题、AniList ID 和目录。不会自动采用同名的旧 TMDB/无标记系列目录。

搜索、详情和活动页通过 `/anime/anilist/<id>` 打开原生目标，并携带当前网盘。AniList 的 HTTPS 海报地址不会再拼接 TMDB CDN 前缀。

## 集数与追更

- 当前支持 TV / TV_SHORT / ONA / OVA，且 AniList 总集数必须是有效正整数。
- 已完结条目以已知总集数确定播出范围；播出中条目使用 `nextAiringEpisode` 和已播出排期。
- 不把未来排期当作已播出，不从标题中的“第三季”推断 TMDB 季度。
- 暂无播出排期时可先加入追踪，状态显示为进度未知；在获得播出证据前不虚构已播集数或执行未来集数获取。
- 集号超出条目总集数时拒绝提交，不自动处理连续总集号偏移。仅有连续总集号、无法证明与条目相对集号关系的资源不会被自动视作对应目标。
- 初次获取、巡检、失败与重试、取消排队、取消追踪都保留真实来源和网盘归属。取消追踪不删除网盘文件。

当前尚不支持原生 AniList 电影、未知总集数的动画、跨季聚合或自动连续集数偏移。

## 可选的旧 TMDB 映射兼容

`MEDIA_TRACK_ANILIST_MAPPINGS` 现在是可选兼容配置。默认留空即可进行原生获取。只有希望某个条目继续使用已有 TMDB 季度目录/追踪记录时，才由管理员比对可信资料后填写整季一一对应映射：

```dotenv
MEDIA_TRACK_ANILIST_MAPPINGS='[{"anilistId":999,"tmdbId":111,"seasonNumber":3,"episodeCount":12,"evidenceUrl":"https://example.com/reviewed-episode-list"}]'
```

示例 ID 和资料 URL 都是占位值。配置了该条目的映射后，会再次校验真实 TMDB 目标及两边集数；失效映射不会静默切换到另一份原生记录。重复映射、无效 JSON、非法 ID 和跨季/部分集数映射会拒绝。映射模式保留原选择到季度 `metadataOrigin`。

Docker Compose 已通过 `env_file` 读取根目录 `.env`。应用新代码需合并功能分支后更新源码并重建、重建容器，例如 `docker compose up -d --build web`。仅改映射环境变量时，重新创建 web 容器即可。之前已部署的镜像不会因为 GitHub 存在新 PR 而自动改变。

## 缓存与故障隔离

请求 8 秒超时；429 尊重 `Retry-After` 冷却。有界进程缓存最多 256 键：搜索 15 分钟、详情 1 小时、榜单 12 小时，同键请求合并。榜单允许额外 7 天历史缓存，之后回退原 TMDB 动漫榜单。缓存重启后丢失，不跨副本共享。

电影和剧集榜单继续使用 TMDB。AniList 错误不会影响 TMDB 搜索或已有 TMDB 任务；已追踪原生条目的详情从数据库读取，在元数据服务暂时不可用时仍可查看。

## 验证与边界

- 全量非 PostgreSQL 回归：358 文件通过、2 文件跳过，4913 测试通过、2 跳过。随后针对未知排期和最终桥接调整，又执行了 89 项相关测试，全部通过。
- PostgreSQL 16 专项：9 文件、140 测试通过，包含原生来源与同编号 TMDB 记录的隔离及准确取消追踪。
- 原生集成测试模拟用户反馈中的 25 集条目：无需映射提交，SQLite 重启恢复，现有 Agent 工具完成两集模拟转存、移动和落地文件复核；随后巡检以 AniList ID 刷新到下一集，保留已经获取的两集。
- Lint、工作流与 Web 类型检查、生产构建通过；桌面端及两个现有 Worker 的类型检查通过。
- Docker 多阶段镜像构建通过。构建验证仅在临时 Dockerfile 挂载本环境公开 CA，未改动仓库的部署架构或关闭 TLS 校验。
- Chromium 使用标注的模拟接口数据验证相同标题的 25 集条目：获取按钮可用、点击入队、来源与集数持久化、媒体库及原生详情链接、AniList 故障时读取已存详情、移动端和取消追踪均通过；测试中禁止 TMDB 请求，未出现页面脚本错误。

模拟 API、模型和网盘测试不代表已从真实网盘获取资源。此前此云环境请求 AniList 实站返回 Cloudflare 403，尚不能替代部署网络中的真实 API/资源源/模型/网盘验收。本次未访问或修改用户的局域网部署。
