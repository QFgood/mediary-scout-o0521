# 从网盘恢复媒体库

重新部署或重建数据库后，先在设置中重新绑定原网盘，在对应网盘的媒体库顶部点击「同步网盘资源」。同步扫描该盘已绑定的 Movies、TV、Anime 分类目录，补回缺失的作品、季度、元数据和已入库集号，并重新核对已有记录。空媒体库也提供入口。

优先按原项目目录的 `{tmdb-数字}` / `{anilist-数字}` 标识定位作品；旧的 `片名 (年份)` 目录只有在片名、年份及电影/剧集类型唯一匹配时才导入。剧集读取 `Season N` 季度目录及文件名中的集号；在已确认作品和季度、且集号不超过已知总集数时，也支持季度目录直接下的原 Agent 的 `001.mkv`、`002.mkv` 等纯数字命名（Season 2 中的 001 对应 S02E01）。此规则不用于搜索结果或任意网盘目录，不把年份、分辨率或超出范围的数字猜成集号；AniList 动画条目仍使用条目自身的相对集号，不把播出季度当成作品季数。视频文件实际存在且大小大于零才恢复已入库状态，字幕、预告、样片和 staging 临时文件不计入。

扫描与复核阶段只读网盘并写入媒体库数据库，不重命名、不移动、不删除文件。已有记录会刷新排期并补上确认存在的集号，不因有界扫描未找到文件就清除原有已入库标记；保留已有目录和画质偏好。完成复核后，对确认缺少的已播集自动排队补集，后台 Worker 随后使用现有资源获取流程转存资源，遵循已有模型、网盘和资源设置。未播集不提交。重复点击可安全重试，活动任务不会重复提交。同一进程中的同盘同步共用正在进行的任务，数据库的原有原子预留也会避让正在获取的作品。部分目录失败不会回滚已经恢复的其他作品。

同步完成后展开「查看需核对内容」核对问题。存在未识别视频、季度不符或元数据无法刷新时，仍恢复可确认的入库事实，但不自动补集，以避免重复获取。已有活动任务的作品暂缓复核和提交，任务结束后可重试；同作品多季因互斥暂缓的任务也会列入报告。元数据不可用、片名不唯一、非标准目录、文件集号与季度不一致等情况不会强行认领。扫描限于每个电影/季度目录下四层文件子目录，网盘其他目录不在范围内。同步不会把文件名无法确认的集数猜成已入库。

界面会显示新增作品/季度、修正项、恢复集/部、复核已有项、确认缺集数、已排队补集任务及待核对项数。进行中或仍缺集的剧集保持追踪状态，完全播出且文件齐全的季度标为完成；自动补集仅在明确识别和无活动任务冲突时排队，不保证资源源中一定有可用资源。旧的聊天、获取历史、源链接和用户设置无法仅从网盘文件重建，仍需数据库备份。
