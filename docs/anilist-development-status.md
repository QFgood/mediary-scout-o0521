仅把统一卡片的 `anilistId` 改名为 `tmdbId` 无法解决上述依赖，会请求错误的作品／季度。
AniList 的 `season: WINTER/SPRING/SUMMER/FALL` 是播出档期，不是作品续作序号。前作／续作关系仅用于浏览独立条目，不推断第几季或集数偏移。

## 已实现

- 独立、无需 AniList 登录或 API Key 的公开 GraphQL 客户端。
- 关键词检索日本动画，保留原生／罗马字／英文标题及收录的别名；不使用 LLM。
- 独立 `MediaIdentity` 联合类型，禁止混用两个来源的 ID。
- TMDB／AniList 确定性字段转译；未知年份／集数保持未知。
- 搜索页来源切换保留关键词和网盘工作区；返回搜索时同时恢复来源。
- AniList 作品详情 `/anime/anilist/<id>`，展示集数、状态、播出档期和前作／续作链接。
- 当前季度、近期热门、即将播出的动画榜单，复用原海报墙。
- 动画海报直达对应 AniList ID 的详情；电影、剧集保持 TMDB。
- 获取按钮展示不兼容原因；服务端拒绝绕过 UI 提交的 AniList 候选。
- 10 秒请求超时、GraphQL／HTTP 错误处理、429 `Retry-After` 冷却。
- 有容量上限的进程缓存与相同请求的并发去重。搜索 6 小时、详情 24 小时、榜单 12 小时；榜单失败可使用额外 7 天历史缓存，随后回退 TMDB。

缓存有意不新增数据库表，容器和桌面版都可用；进程重启后缓存丢失，多副本不共享缓存和限流状态。
AniList 不保证中文译名覆盖；未命中时可尝试日文、罗马字或英文名称。
本扩展遵循项目现有 `HTTP_PROXY`／`HTTPS_PROXY` 出站代理配置，不新增代理服务。
